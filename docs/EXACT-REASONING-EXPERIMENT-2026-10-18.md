# Terminal exact counting experiment

Plain words: A recorded Astra answer returned133 where independent dynamic programming
and exhaustive enumeration both give134. The local controller delegated the original
question unchanged. More local training cannot correct that particular upstream error.

Plain words: The experiment gives Astra a terminal action for counting subsets of
bounded distinct positive integers. Astra chooses whether to use it and supplies the
complete values, target and literal source quotes. The application validates the
quotes and numeric bounds, computes the count, records an actual execution receipt
and speaks that receipt's value. This is a model-selected computational tool. The
spoken result comes from code, rather than an unchecked model-proposed number.
The general API boundary follows [official OpenAI function-calling documentation](https://developers.openai.com/api/docs/guides/function-calling):
the model proposes function arguments and application code executes the operation.

Plain words: One API request per delegation, store:false, at most4096 output tokens.
There is no second formatting request. Plain-text answers remain explicitly unverified
model text. This does not make other reasoning, private access or native speech correct.
Literal quotes do not prove universal semantic selection or complete input extraction.
The fixed evaluation checks those arguments against its authored inputs after execution.

Plain words: The handler supports1–24 distinct positive integers, each at most100000,
and an integer target0–100000. It includes the empty subset for target zero. It rejects
unquoted, changed, signed, fractional, decimal, duplicate and out-of-range inputs.
Only conventional English number-word hyphens are accepted. Existing speech WER
normalization alone would erase signs and punctuation, so extra numeric-boundary checks
prevent interpreting a negative or decimal source as positive integers.

Plain words: Seven local tests check independent exhaustive counts and input/format
rejections. A fixed nine-question API experiment is declared before execution: two
reused development cases, five fresh count cases, an unsupported negative-number case
and an ordinary explanation. Every attempt is retained; no retry until correct, no
hidden oracle in the request and no training approval. The owner demo remains unchanged.
