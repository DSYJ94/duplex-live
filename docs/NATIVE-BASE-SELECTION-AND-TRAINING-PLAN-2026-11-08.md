## Which parameters to train

| Intervention | What changes | When to use |
|---|---|---|
| Data/objective/recipe repair | Coverage, supervision mass, retention and schedule | First when the actual failure is missing/misaligned supervision or interference. |
| Broader LoRA/component adapters | More directions in selected existing matrices | A meaningful PersonaPlex comparator to its old narrow1.8944M adapter, if the released base is viable. |
| Full native LM fine-tuning | Updates selected pretrained language/temporal/depth weights; total model size stays the same | A matched branch when broader adaptation cannot learn the target without losing quality. |
| Acoustic/conditioning adaptation | Changes the speech interface/decoder components justified by raw speech evidence | If correct language does not render faithfully; preserve codec/voice components that already work. |
| Structural upsizing | Adds layers/width/experts/residual modules and genuinely increases total capacity | Only if adequate data/optimisation show a capacity bottleneck, or a tested stronger foundation is unavailable. |

The old PersonaPlex adapter had1,894,400 trainable parameters on13 modules in the last four temporal layers and text head. Current Venus698,351,616-LoRA training is a different architecture/experiment; its failure does not prove that a broader PersonaPlex adapter would fail. The archived PersonaPlex weight file contains8,371,408,896 tensor elements including depth/audio machinery, despite the released7B label; trainable parameter counts must be counted for the chosen configuration. These counts do not measure knowledge or intelligence.

Exact counts from the preserved PersonaPlex safetensors header now give concrete broader-adapter options, rather than guessing. Reproducing the old13-matrix rank8 mask gives exactly1,894,400 coefficients. The same projection/feedforward families across all32 temporal layers plus the text head give105,070,592 at rank64 or210,141,184 at rank128. Adding the packed QKV matrices gives138,625,024 at rank64 or277,250,048 at rank128. These are **proposed LoRA coefficient counts**, not already trained variants, new pretrained knowledge, or proof the higher rank is necessary. The packed projection uses a native weight tensor rather than a normal `Linear` module, so it needs proper streaming/autograd integration; a generic module swap is insufficient. Full arithmetic, tensor shapes and pinned header hash are in [the capacity inventory](NATIVE-PERSONAPLEX-CAPACITY-COUNTS-2026-11-08.json). No weights were loaded or initialized to make this inventory. A selected dense fine-tuning branch can also cross1B **trainable existing coefficients** without enlarging the model: last5 temporal layers plus text head comprise1,158,717,440 exported weight elements (last4:953,188,352). These counts include layer norms and are candidates for native module/parameter validation, not already admitted training. This is different from adding1B randomly initialized parameters to total model size.

Full fine-tuning is a legitimate option, not automatically better or safer. Research finds different learning/forgetting trade-offs for LoRA versus full tuning; it does not prove a universal winner for this voice task. LoRA can also forget, so frozen original weights do not guarantee retained behaviour. [LoRA/full-tuning comparison](https://arxiv.org/html/2405.09673v2), [regularized replay study](https://arxiv.org/abs/2512.22337).

Adding random billion-parameter blocks does not add pretrained knowledge. Function-preserving residual/layer/width expansion is technically possible, but it needs a training corpus, new-state initialization, native cache/latency changes and measured benefit. Low TRAIN loss with poor speech or generalization is not evidence that the model needs more parameters. Try a stronger viable pretrained foundation or the matched full/adapter branch before structural growth by default.
