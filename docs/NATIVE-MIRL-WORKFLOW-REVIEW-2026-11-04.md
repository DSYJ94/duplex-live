# MiRL alongside OPAL — native duplex workflow review

Reviewed 4 November 2026. **Recommendation: use failure profiling and a versioned TRAIN repair queue now; do not add MiRL's RL runtime to the current GPU phase.** This is a proposed voice adaptation, not demonstrated MiRL performance on Venus. No training, data mutation, external judge request or cloud change was performed for this review.

## What the primary research establishes

MiRL identifies recurring wrong actions across tasks, saves the context immediately before each mistake, and trains continuations from those contexts. It reconstructs a terminal environment by replaying earlier commands and retains a prefix only when every recorded output matches. Its reward is task success **AND** avoidance of the targeted misbehavior; successful tasks containing that mistake receive no reward. Its Qwen3.5-4B terminal-agent experiment reports 43–57% fewer measured misbehaviors on unseen prefixes and 51.8% versus 47.4% on Terminal-Bench Lite. These are terminal-agent results, not evidence about duplex timing, speech or Venus. Only 219 of 640 selected prefixes passed reconstruction, illustrating that correct state replay is substantive work. [Paper, sections 3–4](https://arxiv.org/html/2610.35697v1)

The released training script uses four full-weight learners and four rollout GPUs, DeepSpeed ZeRO-3, a TMax/open-instruct trainer and a separate behavior judge. It is not a native speech trainer or an optimizer plugin. Its no-KL recipe must not replace this project's retained KL/hidden objectives. [Actual training script](https://github.com/runchu-tian/MiRL/blob/main/scripts/train.sh)

Official artifacts include [code](https://github.com/runchu-tian/MiRL), a [terminal-agent checkpoint](https://huggingface.co/Rtian/MiRL-Qwen3.5-4B), [training data](https://huggingface.co/datasets/Rtian/MiRL-train) and [evaluation trajectories](https://huggingface.co/datasets/Rtian/MiRL-TB2.1-trajectories). Code is [Apache-2.0](https://github.com/runchu-tian/MiRL/blob/main/LICENSE); the authors specify ODC-BY for TMax-derived data. The dataset card could not be fetched in this review, so its license metadata was not independently checked. Do not import terminal tasks or their benchmark trajectories into voice training. [Authors' artifact/license statement](https://arxiv.org/html/2610.35697v1#A4)

## How it complements our implementation

OPAL addresses **how weights are updated**, using an agent's analysis and optimizer code. MiRL addresses **which recurring decisions need correction and how success is rewarded**. They can coexist, but simultaneous optimizer and curriculum changes would obscure which helped. [OPAL authors' description](https://xingjianbai.com/reactive-optimizers/)

The current large-capacity recipe explicitly selects OPAL `backend='keep'` and a zero agent budget in [large_train.py](../training/venus/large_train.py). It preserves wrapped optimizer/program state, but it is not currently a live code-rewriting agent. Existing [diagnostics.py](../training/venus/diagnostics.py) separates family losses, coverage and possible recipe/runtime causes; [behavior.py](../training/venus/behavior.py) records native frame/event evidence. These are useful inputs to a repair queue, not already a MiRL implementation. Existing [behavior_review.py](../training/venus/behavior_review.py) provides cue, cancellation and task-event measurements; keep their actual provenance and unchanged thresholds.

## Small useful addition after the present result

1. **Profile model behavior separately from infrastructure faults.** Use synthetic TRAIN episodes for mining: pre-cue speech, incomplete delegation arguments, ignored cancellation, speech while paused, stale-result delivery, and omitted/incorrect result use. A CUDA exception or slow transfer enters engineering diagnosis, never a model-behavior training label. Distinguish absent knowledge, wrong control action, bad target and broken rendering before proposing a repair.
2. **Create one append-only repair queue.** Each record needs checkpoint/source/recipe hashes, TRAIN scene and audio hashes, earliest causal frame/event, named error, evidence, recurrence count over distinct situations, proposed correction and uncertainty. Repeated copies of one utterance do not establish broad recurrence. Conflicting judges remain unresolved rather than becoming targets.
3. **Target the next data version.** Select the largest reproducible error family, author matched synthetic scenarios plus ordinary-conversation rehearsal, and qualify every new clip/teacher/semantic conversion through existing gates. Keep the current 304-scene manifest untouched. DEV can reveal a family-level gap, but never copy DEV/HOLDOUT wording, answers, audio or hidden worlds into TRAIN. This supervised repair is **MiRL-inspired**, not MiRL RL.
4. **Measure one intervention.** Compare the same starting checkpoint and optimizer/update budget on existing balanced rehearsal versus the versioned error-targeted mixture, with equal retained coverage. Freeze the optimizer/OPAL policy for that first comparison. Report targeted error frequency over eligible opportunities, full-task success, ordinary retention, speech accuracy/naturalness and latency on complete disjoint cohorts. Lower teacher-forced loss alone does not establish a repair.

## When actual suffix RL would be justified

Only after supervised repairs produce reliably judgeable partial successes should we consider native suffix rollouts. Exact voice replay would need audio chunks/timing, conditioning and KV/audio state, RNG, parser state, worker events/results, pending-task identity, cancellation status and relative clocks. A transcript prefix alone is insufficient. Prove replay equivalence first, then train with an outcome-and-behavior reward; include speech validity so silence cannot game every task. This requires a separate native rollout/log-probability/reward design and scoped experiment, not installation of the terminal package.

**Priority remains the running native gradient/throughput check and the already approved training.** MiRL does not repair CUDA, activation storage or scheduling, and should not create another infrastructure branch before we have that result.
