## Useful SGLang components

The official [PersonaPlex cookbook](https://sgl-project.github.io/sglang-omni/cookbook/personaplex.html) documents a concrete native PersonaPlex implementation: continuous 80ms frames, Mimi audio codes and retained session state without external VAD turn-taking. It supports offline generation and live `/v1/realtime`. The page describes one-GPU deployment and model-specific memory fractions. This makes an evidence-based integration candidate for our eventual product runtime. It does not establish compatibility with our Context Spanning overlay, trained adapters, exact numerical behavior, GH200 ARM environment or native task protocol; those need a focused port/equivalence check after foundation selection. It is not installed here.

The [official interactive-runtime article](https://www.sglang.io/blog/omni-interactive-runtime) separates native duplex models, externally controlled turn-based models and cascades. Its graphs/sessions permit a native conversation model to coexist with asynchronous reasoning. Playback progress determines what belongs in conversation history, and cancellation must invalidate in-flight output. These are directly useful requirements for our live route. The article's results are configuration-specific: a 27B cascade has more grounded replies than its 4B ablation, but the language-model upgrade does not fix their coarse VAD interruption policy. Its small per-category sample sizes preclude ranking architectures from small differences. This supports evaluating reasoning and interaction separately; it does not prove we should replace native duplex with an ASR–LLM–TTS cascade or that a runtime can supply missing reasoning knowledge.

The 9 November [OpenRSI × SGLang-Omni report](https://index.openrsi.foundation/blog/2026/openrsi-sglang-omni/) describes agent-generated serving-code changes validated independently before upstream review. It reports throughput improvements across eight speech/omni models without intentionally changing model weights. Some before/after ranges include other PRs, image changes or changed defaults; certain tail latencies regress. Its own qualification is that WER does not measure perceived speech quality. Useful for our OPAL-adjacent workflow: freeze a representative benchmark and model/data, optimize a measured runtime bottleneck in an isolated branch, verify independently, and promote only complete measured improvements. Do not import headline speedups as GH200/native-duplex evidence or treat code optimization as pretraining, new intelligence or parameter growth. Current matched evaluation stays unchanged.

## Does more training or more capacity make sense?

**Recommendation: substantial reuse of a pretrained native model, broader verified data, then conditional continued pretraining and capacity growth. From-scratch pretraining is not the next product step.** This is our project inference, not a claim established by the SGLang post.

- **Broader supervised post-training first.** Our current matched comparison is the immediate discriminator: foundation-correct/candidate-wrong examples implicate training/retention before foundation ignorance. Compare both adapter capacities against each untouched base. More updates over the same small corpus do not resolve absent knowledge or absent interaction coverage. The prepared1008 reasoning TRAIN examples are a seed, not the substantive mixed reasoning/conversation corpus needed for the next scale phase.
- **Continued pretraining/mid-training is justified for demonstrated native knowledge deficits.** Use licensed general reasoning, technical explanations, mathematics/code and corresponding conversational material, with general/native rehearsal. [Simple and Scalable Strategies to Continually Pre-train Large Language Models](https://arxiv.org/abs/2403.08763) studies learning-rate re-warming/re-decay and replay, including10B models, as an economical alternative to restarting. This supports controlled continued adaptation; it does not establish speech/codec retention for Moshi. For us, preserve a frozen baseline/reference and native text/acoustic/history objectives, begin with the language pathway while protecting codec/speech behavior, then perform native conversational SFT and interaction/routing RL. Select actual token budgets and distributed layout from the admitted corpus and measured throughput rather than inventing a single-GPU completion forecast.
- **Selective/full fine-tuning changes which existing parameters learn.** It can add flexibility beyond LoRA without enlarging the model. Compare it with the best adapter under a matched data/exposure budget before blaming total parameter count. Protect ordinary reasoning and speech with rehearsal, reference retention and held-out native evaluation. This is an inference for our experiment design; no full-tuning run is launched by this note.
- **Adding blocks/parameters is mathematically possible and a conditional research branch.** [Net2Net](https://arxiv.org/abs/1511.05641) formalizes function-preserving growth. [LLaMA Pro](https://arxiv.org/html/2401.02415v2) expands LLaMA2-7B to8.3B using identity-initialized residual blocks, freezes inherited blocks during domain adaptation, and trains the new blocks on code/math data. This is evidence for a trained expansion, not an automatic gain from initialization. Applying the idea to Moshi requires preserving streaming/KV/codec alignment and native outputs initially, then teaching the added capacity. Growth does not automatically import knowledge, prevent all forgetting after learning or improve latency.

## Concrete sequence and stop rules

1. Finish existing evaluation8352856 and inspect all192 outputs; retain the complete foundation/adapter comparisons and historical Venus evidence without claiming incompatible adapters can transfer.
2. Choose a foundation from native reasoning, speech, interaction and connected-backend evidence. Integrate a stronger independently served reasoning model for difficult work while teaching appropriate direct answers and complete-context delegation.
3. Build the broader mixed corpus and a sustained multi-GPU SFT/selective-full-tuning comparison. Use the time-limited20k award productively; actual phase caps and source/data authorizations still apply.
4. If native knowledge remains limiting, execute a defined continued-pretraining branch with replay and native retention, followed by speech/conversation alignment. If fixed-size learning remains capacity-limited, compare identity-initialized block expansion against the best fixed-size tuning run using comparable data and compute.
5. Use RL/MiRL on measurable interaction, routing and recovery failures once rollouts and task rewards are trustworthy. Treat OPAL recipe adaptation and OpenRSI-style runtime search as distinct loops, each with fixed independent acceptance evidence.

The relevant product decision is the cheapest measured route to stronger native competence plus reliable delegation, not the largest trainable-parameter figure. There is currently no evidence that a frontier-scale from-scratch native model is required for this product, nor evidence that extra parameters alone solve the observed failures.


## Reinforcement learning follow-up

Recommend starting a substantive native RL branch from a coherent saved seed as soon as the full comparison identifies one, alongside continued supervised rehearsal. The primary [Moshi/PersonaPlex interaction RL paper](https://arxiv.org/html/2606.11167v2) directly tests this model family. Start with verifiable basic-answer and routing rewards, strict silence/release and pause/interruption waveform rewards, and actual pending/cancel/task receipts. Preserve semantic/speech quality to prevent reward hacking; use GRPO and then MiRL-style repeated-error targeting where native prefix replay is faithful. The implementation and phase proposal must declare trainable set, reference checkpoint, reward version, rollout/learner budget and complete evaluation. RL is not running today.

This is speech/text agreement, not native reasoning accuracy or proof of a fully usable policy. Its compatible checkpoints remain useful potential seeds/teacher material only for independently verified behaviours.
