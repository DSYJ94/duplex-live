# Native text rehearsal: a supported primitive, not an admitted training mode

17 November 2026. Source inspection only; no model execution, cluster access, training or provider calls. Current valid four-GPU frozen-native TRAIN1008 collection job8553179 remains untouched.

## Finding

**The exact pinned LM has enough primitives for a genuine audio-absent next-token language objective. This repository does not yet implement or qualify that objective.** Add one explicit text-rehearsal branch through the existing distributed native dispatch; mix its separately normalised loss with retained native audio/control. Broader verified text need not all become speech, but transfer from text updates to native spoken behaviour must be measured.

This is continued language adaptation / posttraining of an existing PersonaPlex-derived LM, not scratch pretraining and not evidence of restored ordinary text-chat competence. Declarative knowledge replay is a language-model objective; answer-masked QA additionally requires an explicitly qualified textual conditioning convention. Neither is the same as an ordinary user text channel in this duplex architecture.

## What original owners actually provide

Kyutai's [Moshi paper, sections4.4 and5.5](https://arxiv.org/html/2410.00037v2) describes text-only training mixed with speech training and reports spoken-QA degradation without text mixing. This supports retaining language competence through a language objective; it does not establish an optimal replay ratio or an executable PersonaPlex recipe. The [official Moshi README](https://github.com/kyutai-labs/moshi) points to [moshi-finetune](https://github.com/kyutai-labs/moshi-finetune) for adaptation. Its documented input is timestamped transcripts paired with stereo audio, not a general text corpus.

At inspected finetune revision `2acc879fe7c48f885a18f6cc9548bccb2674d87b`, [train.py](https://github.com/kyutai-labs/moshi-finetune/blob/2acc879fe7c48f885a18f6cc9548bccb2674d87b/train.py#L246) computes text and audio losses from model outputs over encoded conversation codes. That is text supervision **within audio training**, not verified text-only rehearsal. [NVIDIA's PersonaPlex README](https://github.com/NVIDIA/personaplex/blob/16419a2ef7b98611f58c9df07477d00e5ad61d5f/README.md) describes text role prompts and voice conditioning; it does not supply the missing replay loader/objective. No exact original text-replay trainer for this released checkpoint was verified in these inspected sources. We should implement and prove the bounded seam below rather than claim an existing ready capability.

## Conditioning is not a standalone language loss

The pinned [sequence convention](https://github.com/mindlogic-ai/Context-Spanning/blob/79df302fa2820cae10c61bb2b7f302c52edb6ed2/contextspan/model/sequence_convention.py) has one text row for assistant text/control, plus8 agent and8 user audio rows. Persona prefixes and backend spans carry SILENCE/SINE audio placeholders and excluded targets. These placeholders are real codec IDs with embeddings, not audio absence. [Span prefill](https://github.com/mindlogic-ai/Context-Spanning/blob/79df302fa2820cae10c61bb2b7f302c52edb6ed2/contextspan/model/context_span_block.py) advances the temporal cache on supplied reference tokens; it does not train next-token text prediction. Do not train gold spans or disguise a user question/gold answer as assistant persona history.

Preserved assisted152 explicit-source diagnostics gave baseline3/64 quantitative2clean and candidate3/64 quantitative3clean; baseline11/12 basic. Plain prefix152 was worse. These supplied task-context results are conditioning diagnostics, not a same7B ordinary text-chat comparison. The27B reference62/64 cannot resolve that distinction either.

## One implementable seam — proposal

Extend [NativeDispatch/NativeView](../training/personaplex/distributed_native.py) with an explicit `text_rehearsal` route and add a separately named objective group beside [matched_losses](../training/personaplex/matched_losses.py). Retain `forward_codes` as the computation, entered through DDP/FSDP's public forward. Do not reuse the existing `text` label as evidence of support: it currently means loss on recorded native multimodal inputs. Do not call the acoustic `forward_train` merely to discard its losses.

Proposed construction for each independent document:

- Let approved tokenizer IDs be `y0…yN-1`. Build17-row inputs with **all16 audio rows set to -1 at every position, including the initial position**. The text row is `[text_initial_token_id, y0,…,yN-2]`; targets are `[y0,…,yN-1]`. Use the exact loaded native text BOS and tokenizer; validate vocabulary and special-token mapping. This is the explicit shift for direct `forward_codes`, not an additional shift after `forward_train`.
- Use ordinary verified explanatory documents first: every valid document token can receive causal CE. For a later qualified answer-masked structured QA format, record the input's textual convention and exclude question/context/delimiter targets while retaining their causal conditioning; predict the first answer token from its preceding prefix. This deliberately trains a text representation, not a supported user-chat interface. Evaluation must disclose it.
- Mask padding, unqualified reserved/control tokens and any supplied-only segments. Do not add RET/action targets to language replay. End-document token handling must be established from tokenizer/source conventions, not assumed from a Hugging Face chat template. Start a fresh cache/position state per independent document; initially avoid packing unrelated documents into one causal context. Bound lengths to measured loaded context without silently truncating needed evidence.
- Normalise by valid text tokens, then apply a separately declared language-mixture coefficient. Existing `coefficients()` balances spoken/clock positions and requires both: it is unsuitable for dense text. Log text tokens, documents, source/family exposure, native real frames/audio targets and each loss/gradient norm separately. Retained distributed replicas already preserve native objective mass; new rank-sharded text needs an explicit global token-weighting contract, not an extra world-size division copied blindly.

For the first implementation, use the existing selective `transformer.*` / `text_linear.*` ownership. Keep text/audio embeddings, output norm and depth/acoustic branches frozen exactly as declared by that mode; if these restrictions prevent useful language adaptation, revise ownership explicitly later rather than silently unfreeze them. Audio-free batches should not create acoustic losses or depth gradients. The retained acoustic objective must still propagate through frozen depth into the **shared temporal trunk**. Frozen depth is not protection against speech change. Mimi stays separate and frozen. Full-native comparison, if used, may have unused acoustic parameters on replay batches; collective/reducer behaviour requires actual proof.

## Bounded qualification, then substantial exposure

Before adding this branch to a long run, prove: zero audio embeddings including BOS; no negative/sentinel targets; exact one-token causality using future-token perturbation; first-answer boundary masking; no prefix/gold leakage; dense forward versus stepped replay parity within declared tolerance/context; and reset/length/packing invariants. Verify selected gradients are finite/nonzero, absent/frozen branches have no updates, and retained acoustic gradients still reach the trunk. These checks should establish the implementation once, not trigger repeated model-start or tiny-pilot spirals. Then run complete declared text/native exposure against fresh disjoint held-outs under the existing substantial-training decision.

[DistributedNative](../training/personaplex/distributed_native.py) already specifies FP32 trainable masters, BF16 compute, FP32 reduction and full sharding for selective/full modes; build Adam after wrapping. [Distributed state](../training/personaplex/distributed_state.py) envelopes full model/optimizer plus hash-bound rank RNG/OPAL state. That code is a seam, not hardware admission: require real native multi-GPU gradient/ownership, memory/throughput and complete save/restore parity, including Adam moments/step, scheduler/text-source cursor, RNG, OPAL updater/program/diagnostics and retained streaming-state boundaries. No adapter-only restore for selective/full LM. Preserve old lineages and immutable source/data hashes.

Finally compare **both** held-out text language/answer competence and fresh native audio-only questions with no typed gold/context assistance. Keep quantitative, broader concepts/technical explanations, uncertainty, actual routing/results, British speech quality, latency, silence/pause/cancel and native micro-turn control separately scored. Text CE improvement is not spoken reasoning improvement; a text-only QA gain is not native user-audio understanding. The route is implementable, but implementation proof, corpus admission and end-to-end transfer remain outstanding.
