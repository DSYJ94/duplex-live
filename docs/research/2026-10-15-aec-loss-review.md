# Echo handling and supervision review — 15 October 2026

Plain words: adopt explicit speaker provenance and echo-resistant microphone input. Do not remove the assistant's own history from attention. The current Lychee training experiment has no user-audio prediction loss to mask, so adding an “AEC loss mask” to that experiment alone would not change its optimization or repair the failed delegation behavior.

This is a source and code review. No model, training objective, microphone pipeline or cluster job was changed for this note. Local file references describe the working tree inspected on 15 October.

## What the supplied PersonaPlex paper establishes

[PersonaPlex, section 3.1](https://arxiv.org/html/2602.06053v1#S3.SS1) receives user audio, agent text and agent audio. Its hybrid prompt places role text on the agent text channel and a voice sample on the agent audio channel. Prompt positions do not contribute training loss; non-semantic audio and padded text losses are down-weighted. This is conditioning and target weighting, rather than a proposed acoustic echo canceller. The released-checkpoint appendix describes a different synthetic-voice recipe and additional Fisher training; results from the experimental model should not be silently treated as results of the released weights. The paper leaves external-tool integration to future work. These claims therefore do not demonstrate successful asynchronous delegation in our repository.

## What Moshi says about streams and echo

[Moshi, sections 3.4.3–3.4.4](https://arxiv.org/html/2410.00037v2#S3.SS4.SSS3) combines separate assistant/user audio streams with assistant text. Temporal inputs sum separate embedding tables; the smaller depth transformer models within-step tokens. Training models the joint sequence, but live inference supplies actual user audio rather than sampling predicted user audio. Keeping prior assistant output in context is part of this design.

[Section 4.4](https://arxiv.org/html/2410.00037v2#S4.SS4) already describes robustness augmentation: a scaled copy of assistant audio is delayed 100–500 ms into the user input; echo and reverb are applied together with 30% probability. Its [loss subsection](https://arxiv.org/html/2410.00037v2#S4.SS4) weights semantic audio more heavily than acoustic codebooks. The described echo augmentation is not token-ID matching or removal of all overlap frames. Separated speaker recordings and simulated separation also form part of the training recipe.

The inference recommendation from this evidence is to preserve separate speakers and realistic overlap, while treating microphone echo as a signal contamination problem. Removing every user frame during assistant speech would remove the interruptions we need the model to hear.

## Three distinct changes

1. **Target eligibility mask:** choose which known labels contribute CE. Correct when preventing a render/assistant sample from becoming a user label, or excluding contaminated labels with unknown clean target. It does not remove echo from model inputs.
2. **Attention/context mask:** prevent a prediction from attending to certain prior tokens. A blanket ban on prior assistant audio changes the pretrained model's conditioning, and could damage continuity, speaker identity and interruption handling. No evidence reviewed here supports imposing it on the current checkpoints.
3. **Waveform acoustic echo cancellation:** use the actually rendered far-end signal to estimate and suppress its contribution to microphone capture before the audio encoder. This operates during inference, when there is no next-token training loss.

The [WebRTC AudioProcessing API](https://webrtc.googlesource.com/src/+/refs/heads/main/api/audio/audio_processing.h) explicitly separates capture `ProcessStream()` from render `ProcessReverseStream()`, exposes stream delay and recommends placing processing close to the audio hardware. That is the appropriate implementation boundary for device AEC. It processes approximately 10 ms PCM blocks; bridge their timing explicitly to our model chunks rather than changing the model's native token rate. Browser capture additionally exposes an `echoCancellation` constraint ([W3C Media Capture and Streams](https://www.w3.org/TR/mediacapture-streams/#dom-mediatrackconstraintset-echocancellation)); requesting a constraint must be distinguished from recording the applied track settings and testing actual echo rejection.

## Proposed mask contract

Implement a shared, pure target-eligibility utility only when broadening native training beyond the current semantic experiment. Inputs should be explicit per-stream/per-frame provenance, not token values: speaker role, target validity, source/played time, prompt/history membership, clean-target availability, echo-only versus double-talk annotation, and encoder receptive-field support. Require source hashes and a channel-layout/version identifier. Missing or ambiguous speaker metadata rejects a training example; do not infer it from audio-token equality.

For a future user-prediction auxiliary objective, the eligibility mask is:

`valid native user target AND genuine clean-user target source AND outside prompt/history-only region`.

If only contaminated microphone targets exist, additionally exclude support annotated echo-only or unresolved; normalize by the remaining weighted target count and report the exclusions. If a paired clean user stem exists, supervise its encoded target even when the *input* microphone signal contains echo: echo-only intervals have clean-user silence as their target, and double-talk retains the real user target. An ambiguous mixed codec token cannot be decomposed by subtracting the assistant token ID. Do not use the fact that the assistant is speaking as a user-label exclusion rule.

For assistant output, retain valid assistant text/audio supervision, including during double-talk. Mask system/voice prompts, padding/undefined targets and disallowed history targets independently. Keep normal silence targets where valid; the task must learn when to remain quiet. Match masks to the existing native delay/shift transforms, and account for encoder receptive fields at interval boundaries. Each head needs its own eligible-count accounting; an empty head either contributes a documented zero term or causes a declared required-head rejection, never an unguarded zero denominator.

For the current Lychee experiment, a useful immediate guard is an assertion that every unmasked label has role `assistant`, modality `text`, and target position after actual result availability. This makes its present objective explicit without pretending it added AEC. Actual input echo robustness requires a separate approved augmentation/audit path through the waveform encoder and cannot be measured by modifying already captured quiet embeddings.

## Concrete implementation seams and checks

- **Data:** extend the approved-ingestion metadata before `lychee_training_inputs.run` builds labels, or before Moshi/Persona native delay conversion. Preserve clean user and assistant stems; optionally produce an echo-contaminated *input* alongside the clean target with recorded gain, delay, room filter and source SHA. Freeze development/test partitions before sampling these transformations.
- **Loss:** apply a role/modality eligibility mask where `labels` are selected in `lychee_semantic_train.loss`, or where per-codebook CE masks are built in `recovery_train.loss_and_metrics` and `personaplex_train.loss_metrics`. Keep it separate from model attention masks. Do not silently claim a user-loss feature when no such head is trained.
- **Runtime:** add AEC at the future real capture/render boundary. The current [concurrent vocoder](../../evals/lychee_concurrent_vocoder.py) and [utterance playout](../../evals/utterance_playout.py) produce causal playback simulation, not an audio device. Reuse their cancellation accounting to define the eventual render reference: only PCM actually presented to the device is eligible, including real buffering/rate conversion/gain. Generated but canceled/unplayed speech is not a loudspeaker echo source.
- **Unit checks:** mask role confusion; prompt and undefined positions; exact native delay/one-token shift; valid overlap preserved; echo-only contaminated labels excluded only when no clean target; clean-user silence retained; repeated identical user/assistant codec IDs do not trigger exclusion; canceled render excluded from AEC reference; interval-boundary/receptive-field handling; no-target batches; distributed numerator/denominator consistency; unchanged baseline logits/labels when feature is disabled.
- **Behavior checks:** separate near-end-only speech, far-end-only playback and double-talk; sweep delay/gain/room response, include interruptions during assistant speech and reference discontinuities after cancellation. Measure false self-interruptions, real user interruption recall/latency, user intelligibility or WER, foreground answer/delegation correctness, and streaming budget. Echo suppression alone is not a pass if it suppresses the user. Use actual device playback/capture for the final test; synthetic echo replay is a component test.

## Decision

Proceed with speaker-provenance guards and an explicit capture/render AEC evaluation plan. Preserve assistant history and real double-talk. Do not spend a larger training run on a nominal user-loss mask in the current Lychee semantic-only trainer: there is no affected loss term. Treat an eventual clean-target/echo-input training ablation as a separate intervention from the ongoing result-response behavior experiment, so its outcome is attributable.

## Addendum: actual 16-head Context Spanning training contract

Plain words: Context Spanning does predict both speakers, so an ownership mask can now affect a real user-audio objective. The previous conclusion about Lychee remains specific to its semantic-only trainer. This addendum inspects Context Spanning source commit `79df302fa2820cae10c61bb2b7f302c52edb6ed2`; it does not change source or launch training.

**Confirm the loaded layout before building labels.** Pinned [finetune.py](https://github.com/mindlogic-ai/Context-Spanning/blob/79df302fa2820cae10c61bb2b7f302c52edb6ed2/contextspan/training/finetune.py) concatenates `[text, agent eight, user eight]`. [loaders.py](https://github.com/mindlogic-ai/Context-Spanning/blob/79df302fa2820cae10c61bb2b7f302c52edb6ed2/contextspan/moshi/models/loaders.py) defaults non-safetensors checkpoints to 16 predicted audio heads; that default alone is not a tensor inspection. Require loaded `audio_offset == 1`, `dep_q == 16`, 17 code channels, 16 output projections and `out.logits.shape[1] == 16`. Audio head indices 0–7 then target code rows 1–8 (assistant); heads 8–15 target rows 9–16 (user).

**Fix the ingestion seam, rather than reversing labels after training.** Pinned [prepare.py](https://github.com/mindlogic-ai/Context-Spanning/blob/79df302fa2820cae10c61bb2b7f302c52edb6ed2/contextspan/training/prepare.py) assumes waveform **left=user, right=agent**. Our [recovery_prepare_data.py](../../evals/recovery_prepare_data.py) and [recovery_teacher_convert.py](../../evals/recovery_teacher_convert.py) write **left=assistant, right=user**. Feeding those approved WAVs directly to upstream preparation reverses the roles. Read named hash-verified stems, or explicitly reorder with a manifest that records the original channel roles. Do not infer roles from amplitude, words or token equality.

The existing [recovery_encode.py](../../evals/recovery_encode.py) cache records the assistant-left/user-right convention and retains all 17 channels. Its pinned `InterleavedTokenizer` encodes both waveform channels independently before flattening them; `keep_main_only=True` filters text alignments, not the user audio channel. Thus user audio has not been discarded. However, historical eight-head training is not a completed approval/audit for a new user auxiliary objective. Revalidate approved **TRAIN** row membership, both stem hashes, native codec hash/vocabulary/frame rate, decoded channel ownership and user valid/padded frame counts. Base recovery preparation audits user clips too; teacher conversion inherits user audio from its source and records its SHA, so traverse that source approval chain rather than treating an assistant-only teacher ASR verdict as a new user audit. Produce a new derived manifest naming the 16-head objective; existing validation/test cache rows must never become optimization examples. Re-encode from approved stems if codec or channel mapping differs.

**Use the native aligned mask at the loss boundary.** Pinned [LMModel.forward_train](https://github.com/mindlogic-ai/Context-Spanning/blob/79df302fa2820cae10c61bb2b7f302c52edb6ed2/contextspan/moshi/models/lm.py#L529) delays each channel, prepends its initial token, runs temporal/depth prediction, then *undelays* logits and returns masks aligned to the original `codes` target positions. Therefore compute CE against `codes[:, 1:17, :]`, with **no additional shift** and no second delay applied to ownership masks. After all prefix/span insertion and any identical crop, compute:

`eligible[B,16,T] = out.mask & amask[:,None,:] & target_role_ok & clean_target_ok & token_in_audio_range`.

For text, intersect `out.text_mask[:,0]`, `tmask` and valid text-target range. Check finiteness on selected logits and gather eligible positions **before** CE: a masked target containing `-1` or the initial-token ID `card` is still invalid input to CE if CE is evaluated over the entire array first. Do not turn nonfinite *eligible* logits into zeros with `nan_to_num`; fail the batch.

**Carry provenance through the actual span transform.** Pinned [sequence_convention.py](https://github.com/mindlogic-ai/Context-Spanning/blob/79df302fa2820cae10c61bb2b7f302c52edb6ed2/contextspan/model/sequence_convention.py) inserts masked context columns and moves acoustic rows 2–8 and 10–16 from frame `f-1` to the final span column. It masks both the inserted block and `amask[f-1]`. Mirror this exact splice in provenance, prepend false eligibility for persona/voice prefix, and crop every tensor identically. For the bounded pilot retain those existing conservative exclusions, including relocated real acoustic tokens: recovering their loss requires a separate native-layout proof. Never reconstruct masks solely from unspliced wall-clock indices.

**Separate speaker objectives explicitly.** Compute a valid CE numerator and target count for each head, then normalize each nonempty head by its own count. Form weighted averages over assistant heads and user heads separately; combine with text as `L_text + lambda_assistant * L_assistant + lambda_user * L_user`. Declare and log both coefficients and all 16 eligible counts. A zero-target head contributes a documented zero and is excluded from its group denominator; reject a batch missing any head declared required. The supplied trainer instead has one pooled audio denominator and sets only head 0 weight to 1, all other 15 to 0.02. If choosing semantic/acoustic weighting for both speakers, explicitly set heads **0 and 8** semantic and the remaining heads acoustic. This changes the supplied objective and must be recorded, rather than described as reproducing it. An assistant-only control uses `lambda_user=0`; retaining a user auxiliary objective uses an explicitly nonzero value.

On clean approved user stems, keep user targets, including silence and genuine double-talk. Assistant-origin tokens are ineligible **as user labels**, but remain valid assistant labels and causal history. With future echo-corrupted inputs, clean user targets remain eligible even during assistant playback; unknown contaminated user targets require exclusion. A loss mask alone does not separate contaminated conditioning.

Required native integration checks: one clean example produces nonzero eligible counts on all 16 heads; role-reversed preparation is rejected; injected assistant-owned user targets yield zero user CE/gradient at those positions; real overlap keeps both speakers eligible; span-boundary and final delayed frames match `out.mask` without double shifting; invalid padding never reaches CE; changing only excluded target logits cannot alter loss; assistant-only versus auxiliary-user objectives report distinct user gradients; and disabled ownership filtering reproduces the supplied valid-data loss before changing its weighting. These establish that the mask is actually consumed by the new loss, rather than merely written to a sidecar.

### Native inference: supplied user codes versus predicted user heads

The pinned [Engine.step](https://github.com/mindlogic-ai/Context-Spanning/blob/79df302fa2820cae10c61bb2b7f302c52edb6ed2/contextspan/model/engine.py#L96) passes `user_mimi.encode(user_pcm)` as `LMGen.step(input_tokens=...)`. The inspected local Engine copy exactly matches that revision (SHA-256 `d9655df5cc72fe7e849d85ac4dd12e74fe662da86d18d01220e51ad42699c9c4`). Its eight input codebooks do not imply that only eight heads are predicted.

The source proof in pinned [LMGen](https://github.com/mindlogic-ai/Context-Spanning/blob/79df302fa2820cae10c61bb2b7f302c52edb6ed2/contextspan/moshi/models/lm.py#L725) is:

1. `needed_tokens = num_codebooks - AUDIO_TOKENS_PER_STREAM - 1` equals eight for the asserted 17-channel model. For user codebook `q=0..7`, `prepare_step_input` writes row `k=9+q` at ring position `(offset + delays[k]) % CT`, and sets that cell's `provided=True`. Row 9 has delay zero; user acoustic rows 10–16 have delay one in the supplied layout.
2. Temporal `input_` reads the preceding ring position. `LMModel.embed_codes` sums all 16 audio-row embeddings and the text embedding, including actual supplied user rows. The native delay determines when each observation reaches that input; it is not a disconnected auxiliary stream.
3. `depformer_step` still computes samples for all 16 heads, but chooses its next depth-conditioning token with `where(audio_provided, actual_target, sampled_token)`. `process_transformer_output` then writes samples to cache only where `provided` is false. Supplied user observations remain in cache, even though the returned raw depth sample array contains user predictions too. `provided` flags for the old consumed input slot are cleared separately from the current target slot.
4. Engine decodes only returned rows `1:9` through the assistant Mimi decoder. Predicted user audio is not sent to the speaker.

There is an initialization exception: at offset zero, native code deliberately initializes the cache with initial tokens and returns no generated frame. The normal persona-prefilled real-input path should already have a positive offset. Record the first real-input offset rather than assuming this exception affects every user frame.

This is static source evidence for the intended wiring, not a runtime observation of the accepted checkpoint. A bounded proof should clone actual user-Mimi IDs immediately before `prepare_step_input`; record offset, delays and per-row write positions; assert identical cache IDs/true flags at those positions before depth prediction; then assert those same supplied target cells survive `process_transformer_output`. Capture the actual temporal `input_` and compare its user rows to the delayed input-ID ledger, including first frame, ring wrap and the first real frame after a span. Check that the input embedding equals the native sum over those captured rows. Collect this passively without new random draws, preserving original IDs/RNG/forward-call order. An identical seeded baseline/capture replay should retain native outputs; a separate reset-state real-user-versus-silence control can establish changed user embeddings/logits without requiring every sampled response token to differ. Keep raw user depth predictions separate from final forced cache/output in the report. This rules out an actual stream-mapping failure before interpreting poor foreground behavior as a training deficiency.
